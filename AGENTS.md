# AGENTS.md — Basrelief

Gyro-driven "3D photo": an image plus a depth map become a displaced relief
surface that moves as you tilt the device. Ships as an Android live wallpaper
with a built-in studio screen.

**Android is the product.** `android/app` is the Android shell; `android/core` is
pure JVM maths and persistence with zero `android.*` imports, so the parts that
are easy to get quietly wrong can be tested without a device. `web/` is a second,
separate product: a browser gallery that reads and writes the app's file and
schema formats. `reference/webgl-port/` is an old Vite + three.js port kept only
as a reference for the original camera model and the embedded-depth reader; it is
not maintained and is not expected to match either product.

Two JavaScript projects, each using **pnpm**: `web/` and
`reference/webgl-port/`. The repository root has no `package.json`; do not add
one. The reference port's demo is `image.png`, `depth.png` and
`photo-with-depth.png` (which carries a `dePH` chunk); replace all three or that
port breaks. Its assets are its own and are not regenerated by the Android demo.

`.design/` is gitignored working material. Its prototypes are **visual
references, not the source of truth for structure** — the filmstrip is the known
case, where a mockup drew the strip outside the sheet and several agents copied
it. Read the code (and fix the prototype in the same change) before trusting a
prototype for anything structural.

## Build and test

Android is built with Gradle inside Podman. The host needs only `podman` (plus
`adb` to install).

```
cd android
./podman-build.sh build-image    # once: SDK image
./podman-build.sh test           # JVM unit tests in :core, no device
./podman-build.sh build-apk      # runs :core:test, then compiles :app
./podman-build.sh install        # build-release + adb install + AOT compile
./podman-build.sh install-debug  # debug APK: behaviour only, never performance
./podman-build.sh build-release  # signed only if keystore.properties exists
./podman-build.sh clean | shell | help
```

`test` only runs `:core:test`; it does not compile `:app`. Any `:app` change must
be checked with `build-apk`. Neither gate can see a GLSL compile error or an
Android-platform `JSONObject.put(String, float)` link error — `scripts/check-shaders.mjs`
and `scripts/check-json-puts.mjs` exist for those, and CI runs them in `guards`.

An installed APK is always `build-release`, followed by the AOT compile
(`cmd package compile -m speed -f`). This ROM has JIT off and ART refuses to AOT
a debuggable app, so a debug install runs interpreter-only and is unusable for
performance work. `install` needs exactly one device; with several attached,
pass `-s <serial>` or set `ANDROID_SERIAL`.

The Gradle cache is bind-mounted out of the container through
`GRADLE_USER_HOME` (not `--gradle-user-home`): the wrapper downloads the
distribution before Gradle starts, so the flag alone re-fetches the zip every
run while everything else stays cached. Override with `GRADLE_CACHE_DIR`, or opt
out with `GRADLE_NO_CACHE=1`.

The JVM suite is **768 tests across forty-five classes**. The count is enforced
by `scripts/check-parity.mjs`; the tests, not this file, are the specification of
what each class asserts.

Web gallery:

```
cd web
pnpm install
pnpm dev        # HTTPS on :5173
pnpm build
pnpm preview
pnpm test       # plain Node, no browser
pnpm typecheck  # tsc --noEmit
```

Reference port (not maintained): `cd reference/webgl-port && pnpm install &&
pnpm run build`; see its README.

CI (`.github/workflows/build.yml`) has jobs `android`, `web-app`, `python-contract`,
`web` and `guards`. The build jobs are filtered by the paths they read; `guards`
runs unconditionally because it checks the document, the contracts and the
shaders.

## Architecture

```
android/app  ──depends on──▶  android/core
  Android shell                pure JVM, zero android.* imports
```

**Two surfaces, one process.** The studio (`MainActivity`) and the live wallpaper
(`DepthWallpaperService`) each own a `GLSurfaceView` and a `ReliefRenderer`.
SharedPreferences `depthwall` is the transport: the studio writes, the wallpaper
reads and re-renders. The wallpaper also writes the index when a playlist rotates
and writes diagnostics, so it is not a pure reader.

The persisted state is versioned JSON in that one preference file: `library`
(the gallery index, schema 5), `config` (legacy app settings), `playlists` and
`jobs` (a running import). **The index owns the selection and only the index** —
a second pointer can disagree with it, and a disagreeing pointer is a wallpaper
showing a photo the user deleted. `AppState` is the single read path; `Framing`
is the single resolution of that state into render values.

**Which surface an engine draws is three questions, not one:** the engine's own
surface, whether the lock screen composites it, and whether the lock screen can
have a second engine at all. Collapsing them either offers a control nothing
reads or refuses one that would work. A lock-only binding is a fact; per-surface
lock *settings* are a promise, and the two are not the same claim.

The index is parsed once per blob change, process-wide, and writers publish it in
memory before the disk write. `AppState.load` therefore sees a just-made edit
immediately even when the stored blob is still behind. The disk write is
serialised on one `index-writer` thread; `LibraryStore.editItem` uses `apply()`
(not `commit()`), because a control release must not block the UI thread. Writes
whose loss would strand the user — add, remove, select — use `commit()`.

**Threading rule:** UI-thread setters may only write `volatile` fields. Anything
touching GL state, including `loadPair` and `screenToOrbit`, must be posted with
`glView.queueEvent`.

## Data model

- A `LibraryItem` is a photograph plus optional depth/normal files, an opaque
  `video` pair, a `splat` cloud and a dimensionless `splat_lens` (the cloud's
  `focal / height`). The row's `focal` is a different number in a different unit:
  a MoGe measurement in pixels of the colour image, used by the card-grid depth
  path. Do not fold the two together.
- Render values live on `SurfaceSettings`, one body per surface (`home`, `lock`),
  seventeen values. `settings(Surface)` is the only read and
  `withSettings`/`editSettings` the only write, so a lock override cannot be
  half-updated. `SurfaceSettings.with` takes **every** value; a single-field edit
  that reconstructs the body must carry the values it is not changing, or it
  resets them.
- The row's `focal` is part of the pair identity: a row that gains one is a
  re-install, and a pair comparison that omitted it would re-decode the
  photograph on every resolve. The cloud's `splat_lens` is deliberately not part
  of that identity, because it is read at draw time.
- `Framing` has **nineteen** float fields and `sameAs` compares every one. A new
  per-surface render value must reach `SurfaceSettings.with` and
  `Framing.ofValues`; a medium/mode value reaches `ofValues` only. Either way it
  must reach `sameAs` and `FramingTest`'s field count, which is the guard that a
  field was not silently left uncompared.
- A clip is **a photograph plus one nullable `VideoTracks`**, not a second kind of
  row. Colour and depth are constructed together; a half-written clip parses as
  no clip at all, so the row degrades to its poster photograph rather than
  rendering a flat, depthless clip.
- **A clip import is one prompt, not a chunk plan.** The server node
  (`MoGeVideoStream`) decodes a window at a time and owns the loop; the app's
  remux sample count is the plan, and a duration-derived frame count is not (a
  240-frame 24 fps range reports 9.9586 s from the muxer). The fixed-name progress
  sidecar may not answer for a run it does not belong to; the prompt id's own
  history entry is the only thing that says the run is over, and
  `status.completed`, not the presence of outputs, is what "over" means. A
  running preview grows in place; a video that rewinds is a photograph.
- `DepthSource.TRACK` offers **Regenerate but not Replace**: the depth clip is
  frame-locked to the colour clip, so replacing it alone would desynchronise the
  pair.
- `Jobs` is the on-disk record of an import. It is keyed by item and carries the
  item, host, prompt id and failure words. A process death inside an import leaves
  a row the user can retry, not an orphaned file.
- The bundled demo is an ordinary preloaded row. It is seeded only when the
  stored index blob is **absent** — a genuinely fresh install, or the reset that
  clears the key — never when the blob is present but empty. That is what makes a
  delete stick. It is file-backed (the raw assets are copied to the row's own
  filenames), and the trio is image, depth and normal plus the demo cloud; an
  unreferenced asset fails silently. `BUNDLED_ID` also refuses a clip: the row
  ships raw assets, so a clip on it would name files that cannot exist.
- **A source state claims nothing while it is still being read.** `DepthSource`
  has `NONE`/`FILE`/`EMBEDDED`/`TRACK`/`UNKNOWN`; `NormalSource` has the
  flat-lit/supplied split plus `UNREAD`; `VideoSource` has `UNREAD` and `POSTER`
  (a clip whose files are gone is not a photograph); `SplatSource` is the fourth
  vocabulary, and `Scene3D` combines depth and cloud so a row with either never
  reads "no 3D". Defaulting an unread state to a negative is the bug these types
  exist to prevent.
- **Playlist rotation writes the index's own selection**, through the same
  selection and `markUsed` calls a user's tap makes, so there is never a second
  pointer. A delete removes the id from the index and every playlist in one
  derivation.
- **A corrupt or newer library blob is handled, never crashes the reader.** The
  Android parser yields an empty index; the web reader keeps the original as
  `library.corrupt.json`. A newer schema is read-only, so no edit, delete or
  clear can overwrite a future build's gallery.

## Shared contracts (`contract/`)

Several rules are implemented in more than one language. The copies cannot share
code, so they share **bytes**: one golden fixture per rule, and every
implementation is tested against it.

| contract | implementations | fixture |
|---|---|---|
| the tag rule | `server/comfy-node/basrelief_depth/contract.py`, `ComfyWorkflow.streamTag`, `web/src/comfy.ts` | `contract/tag/cases.json` |
| the `dePH` chunk | `DepthPng.java`, `reference/webgl-port/src/png-depth.js`, `web/src/deph.ts` (readers), `web/src/pack.ts` (writer) | `contract/deph/` |
| the splat sidecar | `contract.py`, `SplatSidecar.java`, `web/src/splat.ts` | `contract/sidecar/` |
| the `.splat` record | `SplatCloud.java`, `web/src/splat.ts` | `contract/splat/` |
| the settings body | `SurfaceSettings.java`, `web/src/settings.ts` | `contract/settings/` |
| the library index | `Library.java`/`LibraryItem.java`, `web/src/library.ts` | `contract/library/` |

- **The tag rule is ASCII**: keep `[A-Za-z0-9_-]`, then the first 48. Its prose
  was under-defined, and the Python and Java copies had drifted on Unicode and
  truncation units. A wrong answer is silent: the app derives
  `basrelief_<tag>_depth.mp4` from the id, so a one-character difference makes a
  finished import 404.
- **A bad `dePH` payload is refused, not guessed at.** A wrong-size or empty raw
  payload, or raw grey before `IHDR` (where the dimensions come from), is
  `bad-payload`. A whole-PNG payload may legitimately have its own dimensions;
  the reader returns them, and the app layer refuses a map whose size differs from
  the photo rather than stretching it.
- **The `dePH` writer has three rules that each look fine when wrong.** A PNG
  input is never re-encoded (the output is the input's own bytes plus one chunk);
  the chunk goes immediately before the first `IDAT`, after `IHDR`; and the CRC
  is CRC-32 over the chunk type and data, big-endian. `contract/deph/`'s `pack`
  block pins the output and chunk, and `web/src/pack.test.ts` round-trips through
  the reference port's reader as well. A wrong answer is depth on one machine and
  none on another.
- **A ComfyUI run is identified by the prompt id `/prompt` returned.** An absent
  history entry is `running`, not a verdict; a running entry may already carry
  outputs; and only `status.completed` says the run is over. A fixed-name
  sidecar may answer for the wrong run, which is why it is never the poll's
  verdict.
- **A missing sidecar number is "no claim", never zero to divide by.** `focal`,
  `width` or `height` absent, `focal == 0`, or an unreadable body all mean no lens,
  and the cloud draws at the app's documented fallback.
- **The settings ranges are the contract.** Both languages' constants are held to
  `contract/settings/cases.json` by `scripts/check-parity.mjs`; the Java body
  itself has no test that reads the fixture yet, so a body-shape change needs
  review.
- **The library fixture pins the key sets and the schema number.** The Java side
  writes the same keys the TypeScript reader expects; a newer schema is read-only,
  so an old build cannot overwrite a future gallery.

## Invariants and traps

These are the rules that are expensive to rediscover. Each is explained where it
lives; this is the index, not a second copy of the implementation.

### Rendering

- **Origin moves the orbit centre and not the picture; Pan moves the picture.**
  At rest the picture is exactly the photograph translated by Pan alone, at every
  origin and pivot depth. The relief is a turntable about the surface under the
  origin with a fixed rest eye; the splat shifts only by Pan. The crosshair marks
  the orbit centre, not the screen centre. A tap ray-casts into the cloud (or
  unprojects to the plane for a relief), and tapping then resolving is a fixed
  point.
- **Shading is supplied, never derived.** A photo with depth and no normal is
  deliberately *flat lit*; do not reintroduce a depth derivative to make it look
  shaded. The normal is a texture in the OpenGL convention (G is not negated).
- **The depth blur stays in float.** The 8-bit depth terraces become contour
  lines under grazing light; re-quantising the blurred field brings them back.
  `DEPTH_BLUR_FRACTION = 1/78` is checked in all three copies by
  `scripts/check-parity.mjs`.
- **Matrix order is `clip = proj * view * model`.** An unprojection must invert
  `proj * view` in that same order.
- **The depth test must be enabled and the depth buffer cleared**, or far cells
  paint over near ones.
- **Brightness 0 and shadow 0 are the identity.** Brightness is hundredths of a
  stop, so it is exponential; shadow is signed, or "less contrast" is
  unreachable. The default light is derived from the historical vector
  `(-0.35, 0.5, 0.75)`, not chosen as round angles; replacing it relights every
  photo.
- **`Mat4.scaleM` computes `m·S`, not `S·m`.** The expected values in
  `Mat4ScaleTest` were captured from the real Android API; do not hand-derive
  them.
- **`GLUtils.texImage2D` puts bitmap row 0 at `v=0`, which is the bottom.** The
  colour bitmap is flipped vertically so image-top lands at `v=1`, matching the
  top-first depth sampling; flip both or neither. `R32F` textures are NEAREST: a
  LINEAR float texture is incomplete and samples a constant.

### Splat rendering

- **The 3D card grid is derived from `gl_VertexID`**, one card per sample, no
  vertex buffer; the resolution is a uniform. A VBO per sample was tens of MB and
  a multi-second build. The cards are drawn on the ray from the camera **at rest**
  through each sample's reference point, not from the moving eye; feeding the
  moving eye makes every card land on its own pixel and destroys parallax.
- **The aspect goes on X only**, where the relief puts it. Writing
  `(position + corner * size) * aspect` squashes every non-square picture and
  stops the cards tiling vertically. The `h == 0` position must equal the relief's.
- **The colour path is integer.** The 32-byte record is uploaded as two
  `RGBA32UI` texels and unpacked with integer shifts, not as `RGBA32F`: an opaque
  bright colour word is a NaN as a float, and Mali canonicalises it to flat white.
  `contract/splat/` pins the case.
- **The sort is a back-to-front counting sort into 262,144 buckets**, re-derived
  only when the camera moves past the derived gate; alpha blending is not
  commutative, so a wrong order is speckle rather than parallax.
- **The focal scales depth, not the drawing ray.** Drawing the cloud through the
  photograph's focal would re-frame the picture through a different camera; the
  stored focal only decides how much depth there is to reveal.
- **A cloud carries its own lens.** `SplatRenderer.SOURCE_FOVY` is the fallback;
  a stored `splat_lens` is the cloud's own `focal / height`. A new cloud file is an
  identity change; a row that gains a lens is not, because the lens is read at draw
  time.
- **No backdrop.** Gaps opened by a tilt are the clear colour. Two fills were tried
  (a downscaled photograph, then row-median bands) and rejected; the honest fix is
  inpainting, not a second picture behind the first.
- **The near-plane pull-back moves the splat, never the eye.** Pulling the eye
  back changes the projection of every off-plane splat and breaks the at-rest
  invariant. A splat nearer than the minimum is moved along its own view ray,
  keeping its screen position and shrinking its extent. The minimum is derived
  from the splat's own size, not a per-frame scan.
- **A settled cloud draws nothing.** The loop returns while the smoothed tilt is
  within `1e-6` of target and no non-tilt input changed; the residual is below the
  derived sub-pixel bound. A cloud too large for the GPU throws the count and
  texture size rather than drawing nothing.
- **SIZE is a coverage lift, BLUR is a real post-blur.** SIZE stores a fraction of
  the on-screen cell (`0` is no floor, the identity); the old target-area minimum
  was the knob frozen at one cloud's count and was deleted. BLUR is a separable
  Gaussian; it trades detail for softness, and only density regains detail.

### Wallpaper and GL lifecycle

- **The system freezes the wallpaper surface into a snapshot and hides the live
  BLAST surface.** `Engine.isFrozen` is not a reliable statement about what is on
  screen. The first load per engine must therefore be synchronous
  (`ReliefRenderer.setSyncFirstLoad(true)`), or the snapshot is captured empty.
- **A new `onSurfaceCreated` means a new EGL context.** Every cached GL name must
  be forgotten; `hasInstalled` is cleared with the textures. A texture name of 0
  means the install did not happen and must not be recorded as showing.
- **A load can land while the GL thread is parked.** `queueEvent` may run before
  `onResume` with no current context; `install()` returns false for texture 0 so
  the next visibility change retries. An EGL probe, not a GL call, answers "is
  there a context" — `glGetString` on Mali can crash the process.
- **The newest decode wins by sequence, not by arrival.** A large PNG can finish
  after a newer small one; `loadSeq` tags each request.
- **A frame can only be reached by gliding, except `GESTURE` and `PAIR_CHANGE`.**
  `ReliefRenderer.apply(Framing, Apply)` no-ops a `RESOLVE` whose framing matches
  the snapshot or the glide target. The guard lives in `apply`, not at the call
  sites; call sites have been wrong before, and a resolve repainting a glide
  reads as a snap.
- **The lock frame is pre-held on the HOME engine while the screen is dark.** The
  guard must use live interactivity/lock readings, not a constant capability
  reading. A fresh engine inherits the last frame; a surviving one keeps the
  pre-hold.
- **The engine follows the index by itself.** A gallery selection is visible to
  the wallpaper without pressing Set as wallpaper; that button is the system
  picker's apply gesture, not a refresh.
- **No third-party app can re-bind its own live wallpaper.** `setWallpaperComponent`
  needs a signature/privileged permission, and `WallpaperManager`'s public methods
  replace a live wallpaper with a static image. The system picker is the only
  route; do not add a reflection path that can only fail.
- **Never `am force-stop` a package that is the active wallpaper.** Android
  reverts the wallpaper to the default static image, the engine never runs, and
  every later screenshot looks broken. Use `am kill`, or launch the studio and
  press HOME. A reboot is the honest cold test.
- **A view over a `GLSurfaceView` must be positioned by layout, not a post-layout
  transform.** `SurfaceView`'s transparent region is computed from layout
  positions; `setTranslationX/Y` does not trigger a relayout, so a sheet can be
  attached, opaque, touchable and absent from the glass. Change `LayoutParams`
  or call `requestLayout()` on the GL view. `setZOrderOnTop(true)` is the
  structural alternative, at the cost of nothing compositing above the GL content.
- **The dialog blur gate is the theme, not the window type.** A dialog can blur
  when its theme sets `windowIsTranslucent` and has a transparent
  `windowBackground`; `setFormat(PixelFormat.TRANSLUCENT)` does not answer that
  question. `dumpsys SurfaceFlinger` on sdk 37 does not report per-layer blur, so
  the confirmation is the screen.
- **`setStroke` on a `GradientDrawable` clears the fill.** Set the colour after the
  stroke, through one helper that owns the pairing.
- **An invisible view still occupies space.** Fading a band to alpha 0 leaves its
  height; change the height when hiding part of a stack.

### Sheet and gestures

- **The sheet is one panel with one height ramp and a separate shape band.** The
  height follows the hand across the whole travel (`morphProgress`, no plateau,
  no cliff); the width, bottom lift, corner radius and fill wait for
  `SHAPE_BAND_START`, which is the release threshold (`0.95`) so the shape only
  changes where the sheet can no longer rest. The content's opacity has its own
  band at the same line, so no resting position is ever faded. `HEIGHT_BAND_START`
  is gone; do not reintroduce a height band. The sheet rests where released
  (`Snap.FREE`), stores its position in prefs, and the pill returns there.
- **The filmstrip is sheet content** in the Android studio, installed in the sheet
  panel under the grip, and it fades with the sheet. The fix line and photo line
  are sheet content too; the studio has no footer and no Done button. Reset view
  is a row inside the scroll. In the web gallery the current row placement is the
  code's; see `web/README.md`, not a copy here.
- **A web sheet scroll must be hand-driven.** With `pan-y`, the native scroller
  claims the touch at `pointerdown` and sends `pointercancel` as soon as it
  scrolls, so a drag that reaches the top of the list can never become the
  sheet's. `touch-action: none` plus a handoff on each `pointermove` is the
  design, not a preference; wheel and the desktop scrollbar still scroll.
- **A gesture owns the renderer's values for its span; the index is told once, on
  release.** A release that moved nothing writes nothing. The prefs write belongs
  on the UI thread; only the unprojection needs the GL thread.
- **The framing rows are pushed from the renderer, never re-read.** The index
  write lags the gesture, so re-reading storage at gesture end would display the
  value from before the gesture. The exception is a gallery selection or surface
  switch, before the renderer has reloaded.
- **Pan and orbit move a matrix; neither may re-tessellate.** `ReliefMesh.build`
  and `blurredField` belong to a pair change in `install`, not to a framing
  control.
- **The gesture set is the studio's**: tap sets the orbit centre; a one-finger
  drag pans (the relief) or tilts (the web gallery when the sensor is off); two
  fingers pan by their midpoint and pinch Pan Z; the crosshair marks the pivot of
  the frame that was drawn.
- **`apply()` is the only place that decides an instant paint is allowed**, and
  the only escapes are `GESTURE` (a slider must lead the finger) and
  `PAIR_CHANGE` (a different photo; gliding it would smear).

### Sensors, doze and power

- **The doze stops frames while the phone is still, and it is derived, not
  picked.** `CameraModel.DOZE_EPS` is the tilt delta whose worst-case visible
  movement is `DOZE_SUBPIXEL_PX`; the gate watches the **filtered** tilt's
  movement since the last publish, not the raw reading. The same `TiltFilter`
  serves the draw and the gate, stepped at each caller's cadence because the gap
  is a time constant. A running re-centre glide publishes every sample.
- **Do not add a frame-rate gate.** The surface is `RENDERMODE_WHEN_DIRTY`; a cap
  saves nothing and returning early re-presents the previous buffer mid-scanout,
  which tears. Pace at the request site.
- **The gyro is `TYPE_ROTATION_VECTOR`**, re-calibrated on every visibility change
  (never a cached reading), smoothed with the app's time constant so the feel is
  the same at 60/90/120 Hz. After ten seconds of stillness, unregister it and fall
  back to a low-power accelerometer until a shake.
- **Never batch the rotation vector**, and never slow the live sensor to save
  power. The idle accelerometer's batching window is also the worst-case wake
  latency. OS battery-save is the one deliberate exception (50 Hz → 20 Hz).
- **A sensor that cannot change a pixel should not run.** Motion 0 parks the
  sensor; the default is to run, so a caller that does not mention Motion still
  gets parallax.

### Build and packaging

- The manifest has no `package=` attribute; the package lives in
  `android/app/build.gradle` as `namespace` and `applicationId`.
- `--` is illegal inside an XML comment.
- Java 8 source/target.
- The debug keystore is generated on the host and not committed; signing a release
  with it is refused. A contributor's debug builds get their own identity, which
  is what you want.
- `GLUtils.texImage2D` row orientation, the `glPointSize` absence in GLES2, and
  `sample` being reserved in GLSL ES 3.00 are the kind of platform details that
  belong in the code; `scripts/check-shaders.mjs` compiles every shader so they
  cannot take the process down silently.

### Device checks

These cannot be verified off the phone: gyro sign conventions and feel, texture
orientation, live-wallpaper rendering and performance, and OEM immersive
behaviour. Ask the user to check them.

`adb exec-out screencap` is not evidence: it appears to force a redraw, so it can
confirm the fix you just made. Ask for a screenshot taken on the device
(Power + Volume Down) and pull it with `adb pull`. `dumpsys activity top` is fine
for existence and bounds, not for appearance, and child bounds are
parent-relative, so a screen coordinate can land on the picture rather than the
control. With more than one device attached, pass `-s <serial>`; a phone
appearing over Wi-Fi has silently redirected installs.

### Termux notes (host-side, not a build path)

`/tmp` is often not writable; use `$(mktemp -d)`. `#!/usr/bin/env` shebangs fail
(no `/usr/bin/env` on Android), which is why the reference port's pnpm scripts
invoke vite through Node. Shared storage is
`~/storage/shared/Download/`; copy APKs there and install from the file manager,
because launching the installer programmatically is unreliable on some devices.
Everything builds through `podman-build.sh`.

## The web gallery (`web/`)

`web/` is a separate product, not an edit of `reference/webgl-port/`: a static
Vite + TypeScript gallery where a dropped file is shown. The current behaviour,
control inventory, storage layout and ComfyUI wiring live in `web/README.md` and
the code; do not duplicate that inventory here, where it goes stale. The rules
that must not drift:

- **Android owns the design.** A control that exists on both is an Android
  control first. The page reproduces the studio's vocabulary and look from the
  Android code's own constants, not from `.design/prototype/`. A control that
  cannot act is not drawn; a dead enabled control is the lie, and a disabled row
  is only justified when the disabled option is inside a control that is
  otherwise live and it explains itself.
- **The library lives in the browser, and OPFS is its only store.**
  `library.json`, `prefs.json` and one file per row. There is no folder mirror or
  phone sync yet: `showDirectoryPicker` is not dependable on Android Chrome and
  the phone cannot read a `library.json` back, so the format is shared but the
  workflow is not. A real sync is a feature to design, not a button to keep.
- **The gallery is media-typed** — relief, photo, cloud, unreadable — and one
  classifier (`web/src/media.ts`) answers for the card, the count and the viewer.
  A file still being read is not "no depth".
- **The viewer has one dispatch point** (`openViewer` in `web/src/viewer.ts`); a
  second medium is a second `case`, not a renderer interface.
- **The cloud renderer is the Android renderer's**, including the integer colour
  path, the sort and the lens fallback. The relief renderer takes the mesh from
  the reference port and the camera from `CameraModel`.
- **The page stores the app's schemas**, and the agreement is the fixtures in
  `contract/`, never a second implementation compared by eye. The `dePH` reader
  and writer, the splat record, the sidecar, the settings body and the library
  index are all contract implementations.
- **ComfyUI's CSRF check is why the dev proxy strips `Origin`/`Referer`.** It
  compares Origin with the Host it was reached on and answers every POST with
  HTTP 403 otherwise. A static build has no proxy and needs ComfyUI's own
  `--enable-cors-header`; a failed preflight is a sentence naming both routes,
  never a silent nothing.
- **`file:` URLs do not work** (ES modules and fetch refuse them); serve the page.
- A lone `.splat` dropped without a photograph is session-only, because the
  schema gives every row a photograph as its poster. A cloud built from a photo
  persists.

When the page and `web/README.md` disagree, the code wins; report the
contradiction rather than editing the page from this file.

## Known drift (not bugs to fix blindly)

- Default Depth is 90 on Android and 45 on the reference web port; the reference
  port's tilt range scales with zoom, Android's does not. The two are not expected
  to match.
- Depth is a fraction of the reachable maximum, so absolute depth varies with
  zoom. That is intentional.
- The `intensity` pref is 0..100 and is clamped on read, not migrated; values
  written by a 0..200 build are reinterpreted.
- The texture is uploaded without mipmaps, so heavy minification aliases. This
  matters for any render-resolution scaling.
- The reference port's demo assets are its own; regenerating the Android raw
  assets does not touch them.
